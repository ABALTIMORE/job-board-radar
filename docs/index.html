The best roles go to people who apply early and apply on purpose.

See roles first

Companies post on their own boards before aggregators pick them up. Early applicants get read.

Only what's new

It remembers what you've seen, so each run is a short list, not a firehose.

Your filters

Titles, seniority, US or remote or anywhere, and a pay floor using posted salary ranges.

Within the rules

It reads the public endpoints companies publish for their careers pages. Nothing behind a login.

How it works

Four steps, a few seconds per run.

1 · FIND

Locates each job board

Tries likely names on Greenhouse, Lever, and Ashby, and checks the board belongs to that company.

2 · FETCH

Reads open roles

From each board's public endpoint, including posted pay where available.

3 · FILTER

Keeps your matches

Title, level, location, and pay floor, all from one config file.

4 · REPORT

Shows only new

De-duplicated across runs and cities, with a backlog of everything found.

Quick start

Python 3.9 or newer. No packages to install.

  1. Get the code 
    git clone https://github.com/ABALTIMORE/job-board-radar.git
cd job-board-radar
  2. List your companies in a CSV (name, website, optional priority). Start from companies.example.csv.
  3. Set your filters by copying config.example.json to config.json: titles, level, "location": "US", "pay_floor": 150000.
  4. Run it, then open data/new_jobs.md. 
    python job_board_radar.py

Want it to run every morning without your laptop? Use the included GitHub Actions workflow. See the README.

Questions

Is it only for product managers?

No. Change the title patterns in config.json for engineering, design, data, sales, or anything else.

Which companies does it cover?

Any company whose careers page runs on Greenhouse, Lever, or Ashby (many tech companies do). Companies on Workday or custom sites aren't found automatically yet.

Does it apply for me?

No. It finds roles; you decide where to apply and submit yourself.

Is my data shared anywhere?

No. It runs on your machine (or your own GitHub fork) and writes results to a local data/ folder that is never committed.
